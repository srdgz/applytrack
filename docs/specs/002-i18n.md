# 002 · Internacionalización (español e inglés)

| Campo   | Valor      |
| ------- | ---------- |
| Estado  | Aprobado   |
| Versión | 0.1        |
| Fecha   | 2026-10-05 |

## 1. Alcance

- Idiomas: **español (`es`)** e **inglés (`en`)**. La arquitectura permite añadir otros sin tocar código, solo con un catálogo nuevo.
- Se traduce todo lo que ve la persona usuaria: textos de interfaz, mensajes de error, nombres de estados y enumerados, avisos, correos de Supabase Auth y datos del modo demo.
- **No** se traducen los datos que introduce la persona usuaria (empresa, puesto, notas, etiquetas).

## 2. Detección y persistencia del idioma

Orden de prioridad:

1. Preferencia guardada en el perfil (con sesión iniciada).
2. Preferencia guardada en el dispositivo.
3. Idioma del navegador (`navigator.languages`) o del sistema (`expo-localization`).
4. Si nada coincide: **inglés**.

- El cambio de idioma se aplica al momento, sin recargar.
- En la web se actualiza `<html lang>` y el `<title>` de cada ruta.

## 3. Catálogos compartidos

Los textos viven en `packages/i18n` y los usan las dos apps:

```
packages/i18n/
├── src/
│   ├── locales/
│   │   ├── es.json
│   │   └── en.json
│   ├── keys.ts          # tipo MessageKey generado desde es.json
│   └── index.ts         # SUPPORTED_LOCALES, DEFAULT_LOCALE, catálogos
└── test/
    └── parity.test.ts   # comprueba que es y en tienen exactamente las mismas claves
```

- **Formato**: JSON anidado por pantalla o dominio (`board.columns.applied`, `errors.INVALID_STATUS_TRANSITION`), con mensajes en formato ICU para plurales e interpolación.
- **Web**: `vue-i18n`. **Móvil**: `i18next` + `react-i18next` con `i18next-icu`. Los dos leen los mismos JSON.
- **Tipado**: las claves están tipadas. Usar una clave inexistente es un error de TypeScript.
- **Un texto por clave**: no se concatenan fragmentos traducidos para formar frases (el orden de las palabras cambia entre idiomas).

## 4. Relación con la arquitectura hexagonal

- `core` **no conoce el idioma**: devuelve códigos (`DomainErrorCode`, `ApplicationStatus`, `WorkMode`...).
- Las apps traducen esos códigos con convenciones fijas:
  - `errors.<CODE>` → mensaje de error, con interpolación de `meta` (por ejemplo, `{max}` en `FIELD_TOO_LONG`).
  - `status.<status>` → nombre del estado.
  - `workMode.<mode>`, `source.<source>` → nombres de enumerados.
- Un test recorre los enumerados de `core` y falla si a alguno le falta su clave en un catálogo.

## 5. Formatos

Todo con la API `Intl` y el idioma activo, nunca con formatos escritos a mano:

| Dato           | API                                                      | Ejemplo `es`    | Ejemplo `en`       |
| -------------- | -------------------------------------------------------- | --------------- | ------------------ |
| Fecha          | `Intl.DateTimeFormat` (`dateStyle: 'medium'`)            | 5 oct 2026      | Oct 5, 2026        |
| Fecha relativa | `Intl.RelativeTimeFormat`                                | hace 3 días     | 3 days ago         |
| Salario        | `Intl.NumberFormat` (`style: 'currency'`, sin decimales) | 35.000 €        | €35,000            |
| Porcentaje     | `Intl.NumberFormat` (`style: 'percent'`)                 | 42 %            | 42%                |
| Listas         | `Intl.ListFormat`                                        | Vue, React y TS | Vue, React, and TS |

- Las fechas se guardan en UTC (`timestamptz`) o como fecha sin hora (`date` para `appliedAt`), y se muestran en la zona horaria del dispositivo.
- La búsqueda no distingue tildes (`normalize('NFD')` en local, `unaccent` en Supabase).

## 6. Diseño preparado para traducción

- Los textos en inglés suelen ser más cortos que en español, que puede ocupar un 30 % más. Ningún botón ni columna depende de un ancho fijo pensado para un idioma.
- Las pruebas E2E web y las capturas de revisión se hacen **en los dos idiomas**.
- No hay texto dentro de imágenes.

## 7. Criterios de aceptación

- [ ] Ninguna cadena visible está escrita directamente en un componente. Lo comprueba una regla de lint (`@intlify/vue-i18n/no-raw-text` en web y `i18next/no-literal-string` en móvil).
- [ ] El test de paridad de claves pasa.
- [ ] Todos los códigos de `core` tienen traducción.
- [ ] Al cambiar de idioma se actualizan fechas, cifras, estados y errores ya mostrados.
- [ ] El modo demo carga sus datos de ejemplo en el idioma activo.
